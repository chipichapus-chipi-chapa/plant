# Там, где растёт

Уютная браузерная игра с пиксельной графикой: заброшенный сад оживает вместе с реальными привычками игрока.
Отмечаешь привычку — получаешь Семена жизни и осколок кристалла её категории, тратишь их на сад и магию.
Пропуски ничем не наказываются.

> **Статус:** работает первая глава. Месячный трекер привычек, Семена жизни и осколки шести кристаллов,
> лавка, посадка и рост растений, первая магия (пробуждение каменной чаши), исследование тайников,
> коллекция артефактов и Солнечные искры. Что сделано по ТЗ кристаллов и как это проверить —
> [docs/design/crystals-status.md](docs/design/crystals-status.md). Архитектура — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Как играть

Сад — в центре экрана. **Стрелки или WASD** — идти, **E или пробел** — действие с тем, что перед персонажем
(осмотреть, посадить, поговорить) — над такими объектами загорается «!». На телефоне ведите пальцем по саду,
маленькая кнопка ✋ в углу — действие. Строка «Задание от Вереска» и покачивающийся «!» над целью подскажут, что делать дальше.
Нажмите на объект с «!» — откроется описание. Мастер Вереск стоит у грядок — «!» над ним значит, что ему есть что сказать.
В сарай можно войти — просто подойдите к двери: там письмо прежнего садовника и ящик с замком-загадкой.

Кнопки под садом открывают окна:

- **Привычки** — месячный трекер. Отметка сегодня даёт Семена жизни и осколок цвета привычки.
- **Лавка** — пакетики семян за Семена жизни. Посадка — клик по пустой грядке.
- **Сумка** — осколки кристаллов и вещи.
- **Коллекция** — найденные артефакты и силуэты ещё не найденных.

Мерцание над постройкой значит, что там можно что-то найти. Концепция кристаллов — [docs/design/crystals.md](docs/design/crystals.md).

## Стек

| Часть | Технологии |
|---|---|
| Frontend | React 19, TypeScript, Vite, CSS Modules, свой рендер сада на Canvas 2D |
| Backend | Java 17, Spring Boot 4, Spring Data JPA, Bean Validation, REST |
| База | PostgreSQL 16, миграции Flyway |
| Тесты | JUnit 5 + Testcontainers (настоящий PostgreSQL), Vitest |

## Что нужно установить

- **JDK 17+** (именно JDK с `javac`, а не JRE)
- **Node.js 22** (версия записана в `.nvmrc`; с nvm: `nvm use`)
- **Docker** с Docker Compose v2 — для базы и для backend-тестов

## Запуск локально

1. Создать `.env` из примера и вписать любой пароль для локальной базы:

   ```bash
   cp .env.example .env
   ```

2. Поднять PostgreSQL (порт на хосте — 5434):

   ```bash
   docker compose up -d
   ```

3. Запустить backend на http://127.0.0.1:8081 (пароль БД он читает из того же `.env`):

   ```bash
   cd backend && ./mvnw spring-boot:run
   ```

4. В другом терминале запустить frontend на http://localhost:5173:

   ```bash
   cd frontend && npm install && npm run dev
   ```

Если `java -version` показывает не 17+, укажите JDK явно, например
`JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./mvnw spring-boot:run`.

## Проверки

```bash
cd backend && ./mvnw verify
```

```bash
cd frontend && npm run lint && npm test && npm run build
```

Backend-тесты сами поднимают одноразовый PostgreSQL в Docker, поэтому база из `docker compose` им не нужна.

## Графика

Временные спрайты генерируются скриптом и уже лежат в `frontend/public/assets/`. Пересобрать атлас после правок скрипта:

```bash
cd frontend && npm run atlas
```

## Telegram

Игра открывается как Telegram Mini App: сайт на GitHub Pages, сервер на Render, база в Neon,
вход — по подписи Telegram. Настройка и устройство — в [docs/DEPLOY.md](docs/DEPLOY.md).

## Локальный режим и его ограничения

Без `TELEGRAM_BOT_TOKEN` в игре **нет авторизации** — это осознанный режим разработки, а не «вход понарошку»:

- backend слушает только `127.0.0.1`, поэтому из сети он недоступен (при другом адресе сервер не стартует);
- в игре один игрок, все данные лежат в локальной базе;
- для публичного сервера задаётся `TELEGRAM_BOT_TOKEN` — тогда каждый игрок входит через Telegram.

## Сбросить локальный прогресс

Удалит базу вместе со всеми данными игры:

```bash
docker compose down -v && docker compose up -d
```

## Заметки по окружению

- `backend/.mvn/settings.xml` изолирует сборку от глобального `~/.m2/settings.xml` (например, корпоративных зеркал) и берёт зависимости из Maven Central.
- Порты 5434, 8081 и 5173 выбраны, чтобы не конфликтовать с другими сервисами на машине разработки. Порт базы задаётся в `.env`.
