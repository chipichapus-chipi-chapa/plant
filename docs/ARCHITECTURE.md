# Архитектура

## Общая схема

```
Браузер ── React UI (панели, диалоги, формы)
   │        └─ GardenCanvas: свой рендер тайлов на Canvas 2D
   │  fetch /api/*  (в dev — через прокси Vite)
   ▼
Spring Boot (REST, Bean Validation, ошибки в формате Problem Details)
   ├─ player   — профиль и текущий игрок
   ├─ habit    — привычки и их выполнения
   ├─ economy  — росинки, инвентарь, магазин
   ├─ garden   — карта сада и размещённые объекты
   └─ content  — каталог растений и предметов (данные, а не код)
   ▼
PostgreSQL (схема только через Flyway; CHECK и UNIQUE — последняя линия защиты)
```

**Главный принцип:** клиент только сообщает о намерении («отметь привычку», «купи семя», «посади на (3,4)»).
Дату, награду, цену, стадию роста и баланс считает сервер, а клиенту возвращает новое состояние.

## Принятые решения

### 1. Свой рендер на Canvas 2D вместо Phaser (и после появления ходьбы)
В MVP сад — это сцена, с которой работают мышью: наведение, выбор клетки, посадка, клик по объекту.
Хождения персонажа, физики и камеры нет. Для этого хватает тайловой карты, атласа спрайтов и целочисленного масштабирования.
Phaser живёт в собственном цикле со своим состоянием, и его пришлось бы синхронизировать с React.
Рендер изолирован в `frontend/src/game/`. Когда персонаж начал ходить, этого по-прежнему хватило: игровой цикл
(`requestAnimationFrame`), столкновения по сетке клеток и джойстик — около 300 строк без движка. Phaser имеет смысл,
когда появятся камера по большому миру, физика или много анимированных объектов.

Тайлы 32×32, сад 16×10 тайлов. Сад рисуется с целым масштабом (×1/×2/×3) и `imageSmoothingEnabled = false`.

### 2. Локальный режим без авторизации
Один игрок создаётся автоматически, backend слушает только `127.0.0.1`. Кто «текущий игрок», решает
одно место в коде (`CurrentPlayer`), а все таблицы с самого начала привязаны к игроку.
Настоящий вход (Spring Security, BCrypt, cookie-сессия, CSRF) будет отдельным этапом до любого деплоя.

### 3. Рост растений от реального времени
Стадию растения сервер вычисляет при чтении: `planted_at` плюс длительности стадий вида. Фоновые задачи не нужны.
Растения не вянут и не погибают. Привычки дают ресурсы, а время в саду просто идёт, и дни отдыха ничего не ломают.

### 4. Защита от повторного начисления награды
- «Сегодня» вычисляет сервер по часовому поясу из профиля, клиент дату не передаёт.
- `habit_completion` имеет `UNIQUE (habit_id, completed_on)`: одна отметка в день на привычку.
- Отметка — идемпотентный `PUT …/completions/today`. Первый вызов возвращает 201 с наградой, повторный — 200 без награды.
- Вставка выполнения и начисление идут в одной транзакции. Если два запроса пришли одновременно, второй упирается в UNIQUE.
- Списания делаются атомарным `UPDATE … SET qty = qty - :n WHERE qty >= :n`, плюс `CHECK (… >= 0)` в базе.

### 5. Все ресурсы — в одном инвентаре
Семена жизни, осколки кристаллов, пакетики семян и (позже) Солнечные искры хранятся строками
`inventory_item`, различаясь видом предмета в каталоге (`CURRENCY`, `SHARD`, `SEED`, `DECOR`).
Поэтому у всех ресурсов одна атомарная операция начисления и списания и один `CHECK (quantity >= 0)`,
а награда описывается списком «предмет × количество». Новая валюта — это строка в каталоге, а не новая колонка.

### 6. Награда за привычку и дневной лимит
Отметка даёт 3 Семени жизни и 1 осколок категории привычки, если категория задана.
Первые 6 отметок за день приносят награду, следующие засчитываются без неё: так нельзя
нафармить ресурсы, создав 30 привычек «моргнуть». Все числа лежат в `game.rewards.*` в `application.yml`.
Каждая операция игрока над ресурсами блокирует строку его профиля (`SELECT … FOR UPDATE`),
поэтому параллельные запросы выполняются по очереди, и лимит считается без гонок.

### 7. Покупки с ключом идемпотентности
На каждое нажатие «Купить» клиент создаёт UUID и отправляет его в заголовке `Idempotency-Key`.
Пара (игрок, ключ) уникальна в `shop_purchase`. Если ответ потерялся в сети и игрок нажал ещё раз,
клиент отправит тот же ключ, а сервер вернёт уже сделанную покупку и не спишет второй раз (тот же приём, что у платёжных API).
Списание — один `UPDATE … WHERE quantity >= :cost`: баланс не может уйти в минус даже при параллельных запросах.

### 8. Java 17
Spring Boot 4 поддерживает Java 17+. На машине разработки полный JDK установлен только для 17
(Java 21 там без компилятора). Чтобы перейти на 21, достаточно поменять `java.version` в `pom.xml`.

### 9. Testcontainers для backend-тестов
Гарантии целостности держатся на PostgreSQL: UNIQUE, CHECK, блокировки строк. H2 ведёт себя иначе,
поэтому тесты идут на настоящем PostgreSQL в одноразовом контейнере.

## Модель данных вертикального среза

| Таблица | Ключевые поля | Ограничения |
|---|---|---|
| `app_user` | id, created_at | в локальном режиме одна запись |
| `player_profile` | user_id, display_name, timezone | |
| `crystal_category` | key, name, color, meaning | контент, 6 категорий |
| `habit` | id, player_id, title, crystal_category, created_at, archived_at | уникальное имя среди активных привычек игрока |
| `habit_completion` | id, habit_id, player_id, completed_on, life_seeds, shard_item_key | `UNIQUE (habit_id, completed_on)` |
| `plant_species` | key, name, stage_minutes[] | контент, заполняется миграцией |
| `item_def` | key, kind, price, species_key, crystal_category | контент; на категорию ровно один осколок |
| `inventory_item` | (player_id, item_key), quantity | `CHECK (quantity >= 0)` |
| `shop_purchase` | id, player_id, idempotency_key, item_key, quantity, cost | `UNIQUE (player_id, idempotency_key)` |
| `garden_object` | id, player_id, garden_key, x, y, kind, species_key, planted_at | `UNIQUE (player_id, garden_key, x, y)` |

Дальше — квесты, наставник, расчистка участков, декор и внешность персонажа (см. «Отложено»).

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/state` | состояние игрока: «сегодня» по его поясу, инвентарь, привычки, награды дня, растения в саду со стадиями |
| GET | `/api/catalog` | категории кристаллов, растения, предметы с ценами, карты локаций (сад, сарай) с дверями, рецепты, артефакты, места находок и загадки (без содержимого и ответов) |
| POST | `/api/habits` | создать привычку `{ title, crystalCategory \| null }` → 201 |
| PUT | `/api/habits/{id}` | изменить название и категорию |
| DELETE | `/api/habits/{id}` | убрать в архив (полученные награды остаются) → 204 |
| PUT | `/api/habits/{id}/completions/today` | отметить «сделано сегодня»: 201 с наградой или 200, если уже было |
| PUT | `/api/habits/{id}/completions/{yyyy-mm-dd}` | отметка за день: сегодня — с наградой, прошлые дни (до 62 дней назад) — запись без награды |
| DELETE | `/api/habits/{id}/completions/{yyyy-mm-dd}` | снять отметку с прошлого дня; сегодняшнюю снять нельзя (409) — награда уже выдана |
| GET | `/api/habits/history?month=yyyy-MM` | отметки активных привычек за месяц — для трекера |
| POST | `/api/garden/plantings` | посадить `{ x, y, seedItemKey }` на свободную грядку → 201 с растением и стадией роста |
| POST | `/api/garden/weedings` | прополоть заросшую грядку `{ x, y }` → 201 и сколько осталось; 409 — нет лопаты и граблей или уже прополота |
| POST | `/api/puzzles/{key}/attempts` | открыть замок `{ answer: [символы] }`: всегда 200 (`solved` и награда один раз); 400 — комбинация не по форме замка |
| POST | `/api/magic/recipes/{key}/cast` | применить рецепт: списать ингредиенты и пробудить объект → 201; 409 — не хватает или уже пробуждён |
| POST | `/api/exploration/spots/{key}/search` | осмотреть место находки: `FOUND` (награда, артефакт) / `EMPTY` (уже найдено) / `LOCKED` (пока не найти) — всегда 200 |
| POST | `/api/shop/purchases` | купить `{ itemKey, quantity }` с заголовком `Idempotency-Key: <uuid>`: 201 или 200 при повторе |
| GET | `/actuator/health` | жив ли сервер и есть ли связь с базой |

Ошибки всегда приходят в формате Problem Details (`{ title, status, detail }`).

## Экран и окна

Сад занимает всю ширину, под ним — табличка о выбранной клетке и панель из нарисованных кнопок-табличек
(«Привычки», «Лавка», «Сумка»). Каждая кнопка открывает окно поверх сада (`ui/Window.tsx`: Escape, клик
по затемнению, возврат фокуса). Боковых панелей нет — сад всегда главный.

**Трекер привычек** (`features/habits/HabitTracker.tsx`) — месячная таблица: привычки по строкам, дни по столбцам,
недели (1–7, 8–14, …) окрашены цветами кристаллов; сверху мини-календарь с листанием месяцев и столбики
отметок по дням, снизу — число отметок за день, справа — за месяц. Логика дат вынесена в `trackerModel.ts` и покрыта тестами.

- Отметка **сегодня** приносит награду (как раньше). **Прошлые дни** — честная запись в дневнике без награды:
  историю можно вести, но «дозаполнить» месяц ради ресурсов нельзя.
- «План» и проценты выполнения намеренно не показываются: в игре нет обязательств, а проценты быстро становятся упрёком за отдых.

## Экран

- **Игра на всю страницу, без полос.** Масштаб «на весь экран» (`coverScale`): сад заполняет окно целиком, а если
  пропорции не совпадают, лишнее показывает **камера** (`cameraAt`) — герой по центру, края карты не выходят за экран.
  Клик по экрану переводится в клетку с учётом камеры. Интерфейс лежит поверх компактно: сверху — кнопка
  «Задания · N» с выпадающим списком (задание Вереска и поручения жителей) и счётчик семян, снизу — табличка
  о предмете и кнопки-иконки (с настройками).
- **Заставка** при запуске: название, кошка Мята между лилиями, «Нажмите, чтобы начать». На телефоне нажатие
  заодно просит полный экран и горизонтальную ориентацию; в вертикальном положении — «Поверните телефон».
- **Персонажи — без промежуточных кнопок**: нажал на жителя — если поручение можно выполнить, вещи сразу отдаются
  и он благодарит; иначе разговор. Вереск — сразу разговор.
- **Настройки** (полный экран, яркость сумерек, строки монитора, светлячки, скорость текста) — удобства устройства,
  поэтому хранятся в браузере (`app/settings.ts`), а не на сервере.

## Ходьба

- **Управление**: стрелки или WASD — идти, E / пробел / Enter — действие; на телефоне (`pointer: coarse`) —
  экранный джойстик и кнопка ✋ под садом. Мышью по-прежнему можно выбрать любую клетку.
- **Логика** — `game/movement.ts` (чистые функции, покрыты тестами): позиция ступней в логических пикселях,
  проходимость клеток (забор, постройки, растения и наставник — препятствия; пустые грядки проходимы),
  оси двигаются по отдельности, поэтому вдоль забора персонаж скользит.
- **Клетка перед персонажем** описывается в табличке под садом, но рамкой не выделяется. Если с ней можно
  что-то сделать (тайник, чаша, калитка, свободная грядка при семенах в сумке, Вереск), над объектом загорается
  золотой «!». Действие нажимает главную кнопку таблички; перед Вереском — «Поговорить».
- **На телефоне** сад сам служит невидимым джойстиком: ведёшь пальцем — персонаж идёт, короткое касание —
  рассмотреть клетку. Маленькая кнопка ✋ в углу сада — действие.
- **Игровой цикл** в `GardenCanvas`: ввод → шаг → отрисовка, но кадр перерисовывается только при движении
  или изменениях. Свежие пропсы цикл читает из ref, поэтому React не перезапускает его на каждый рендер.

## Сад на экране

- **Карта** — контент: `backend/src/main/resources/content/gardens/home.json`. Тайлы записаны строками
  символов, легенда описывает каждый символ (название, описание, можно ли сажать), постройки лежат поверх.
  Backend проверяет карту при старте (размеры, неизвестные символы, постройки за краем) и отдаёт её в `/api/catalog`.
- **Спрайты** — атлас `frontend/public/assets/atlas.png` + `atlas.json`. Сейчас их рисует скрипт
  `npm run atlas` (`frontend/scripts/build-placeholder-atlas.mjs`) по правилам [ART_DIRECTION.md](ART_DIRECTION.md).
  Чтобы подключить настоящую графику, достаточно заменить оба файла, сохранив имена кадров.
- **Рендер** — `frontend/src/game/`: `layout.ts` (чистая геометрия: кадр клетки, забор по соседям,
  клетка под курсором), `renderer.ts` (слои: земля → постройки → подсветка), `GardenCanvas.tsx` (React-обёртка).
  Масштаб подбирается под ширину и высоту экрана (до ×3), чтобы под садом помещались табличка и кнопки. Клетку можно выбрать мышью или стрелками.
  Сцена рисуется во внеэкранный буфер 1:1 и переносится на экран одним масштабированием, поэтому между тайлами нет швов.
- **Растения** хранятся в `garden_object` с `UNIQUE (player, сад, x, y)`. Стадию вычисляет `PlantGrowth`
  по `planted_at` и длительностям стадий вида. Клиент получает `nextStageAt` и в этот момент тихо перечитывает состояние.
  Посадка проверяет клетку по карте (грядка, не постройка, не занята), списывает пакетик и создаёт растение в одной транзакции.

## Магия

- **Рецепт** (`recipe_def` + `recipe_ingredient`) — данные: какие предметы нужны, чтобы пробудить постройку с карты.
  Первый рецепт: 2 осколка изумруда + 1 осколок аметиста → «Каменная чаша» пробуждается, в ней светятся цветы.
- **Состояние объектов мира** — `player_world_object (player, object_key)`: строки нет — объект спит.
  Первичный ключ не даёт пробудить объект дважды.
- Применение рецепта: блокировка профиля → проверка «ещё не пробуждён» → полный список недостающего
  (если что-то не так, ничего не тратится) → списание всех ингредиентов → запись состояния. Одна транзакция.
- `ContentConsistency` при старте проверяет, что каждый рецепт ссылается на существующую постройку карты.
- Чтобы добавить рецепт, нужны строки в `R__content.sql`, постройка в `home.json` и два кадра атласа (`prop_<kind>` и `prop_<kind>_awakened`).

## Исследование и коллекция

- **Места находок** (`discovery_spot` + `discovery_spot_reward`) привязаны к постройкам карты. Каждое обыскивается
  один раз: `player_discovery (player, spot)` — первичный ключ, повторный поиск возвращает `EMPTY` без награды.
- Место может требовать пробуждённый объект (`requires_awakened`): тайник в сарае виден только при свете
  пробуждённой каменной чаши. Важная находка зависит от продвижения, а не от удачи; попытка «в темноте» ничего не тратит.
- **Артефакты** (`artifact_def`) — уникальные кристаллы с описанием, легендой, подсказкой и эффектом.
  `player_artifact (player, artifact)` не допускает дублей; артефакты не расходуются ни одним действием.
- **Солнечные искры** (`sun_spark`) — отдельная валюта за значимые открытия. Первая трата — рецепт
  «Солнце для калитки»: искра открывает калитку на восток (тот же механизм рецептов, что и у чаши).
- Над постройками с ненайденным содержимым мерцает искорка — подсказка «здесь стоит поискать».

## Персонаж и наставник

- **Внешность** — слоты и варианты в каталоге (`appearance_slot`, `appearance_option`), выбор — `player_appearance`.
  Спрайт собирается из слоёв и перекрашивается на лету (`src/game/character.ts`), см. [ART_DIRECTION.md](ART_DIRECTION.md).
  При первом входе — окно «Новый садовник» (`player_profile.onboarded_at`).
- **Мастер Вереск** — контент `content/mentor/vereshk.json`: разговоры как граф реплик (переходы, варианты ответа),
  шаги обучения и случайные фразы. Граф проверяется при старте (битый переход роняет запуск).
- **Обучение** засчитывается по реальным действиям (`Condition`: привычка создана, награда получена, посадка,
  взаимодействие с миром) — сервер проверяет данные игрока, а не нажатие «далее».
- `player_flag (player, flag)` — что уже случилось; PK делает флаг и связанный подарок одноразовыми.
  `POST /api/mentor/dialogues/{key}/finish` принимает только уместный сейчас разговор (или случайную фразу),
  поэтому шаг нельзя «проскочить», а подарок — получить дважды.
- Вереск говорит, только когда его позвать; «!» над ним — только если есть новость (знакомство, поручение
  или выполненный шаг).
- **Поручения** — те же шаги, но с разговором `offer`: пока Вереск его не провёл, задание на экране —
  «Мастер Вереск хочет о чём-то попросить», и поручение надо получить, даже если дело уже сделано.
  Первое поручение: снять лопату и грабли с забора (`TOOLS_TAKEN`) и прополоть заросшие грядки (`BEDS_WEEDED`).
- **Направление к заданию** (`game/guidance.ts`): над садом строка «Задание от Вереска», над целью покачивается «!» —
  в игре один знак, без стрелок. Цель шага задана в контенте (`target`: кнопка панели, постройка или тип клетки);
  над кнопкой-целью тоже «!». Выполненный шаг ведёт обратно к Вереску; без семян посадка сначала ведёт в лавку;
  если цель снаружи, а игрок в сарае, «!» горит над дверью.

## Локации, загадки и прополка

- **Локации** — карты в `content/gardens/*.json`: домашний сад (`home`), сарай изнутри (`shed`),
  Восточная тропа (`east`) за калиткой, двор поместья (`manor`) за чащей и кухня поместья (`kitchen`). У двери может быть `requires` — постройка, которую сначала надо
  пробудить: калитка в ежевике ведёт на тропу, только когда её открыли.
  У постройки может быть `door` (куда ведёт, в какую клетку, куда смотреть) и `read` (текст письма).
  Где стоит игрок, знает только клиент: позиция не влияет на награды, поэтому серверу её хранить незачем.
  Подошёл к двери и упёрся в неё — экран ступенями гаснет, персонаж оказывается по ту сторону, экран проявляется
  (кнопка в описании двери делает то же). При «уменьшить движение» переход мгновенный.
  Ключи построек уникальны во всём мире, двери проверяются при старте.
- **Загадка с ящиком** (`puzzle_def`): замок из колёсиков с символами. Ответ хранится только на сервере —
  в каталог уходят символы и число колёсиков. Неверная попытка ничего не стоит и не записывается,
  правильная выдаёт награду один раз (`player_puzzle`). Подсказка — в письме прежнего садовника.
  Награда — ремонтный набор: им чинят тачку обычным рецептом (`repair_wheelbarrow`, кнопка «Починить»).
  Замок открывается крупным планом поверх сада (`LockOverlay`): мышью или клавишами, при ошибке вздрагивает,
  при успехе дужка выскакивает и замок падает.
  В кухне поместья ещё две загадки: буфет (подсказка — рецепт варенья на столе) и музыкальная шкатулка
  (подсказка — «Садовый календарь» на полке; внутри луковица розовой лилии, её можно посадить у себя).
- **Прополка** (`player_tile`): нужны лопата и грабли из тайника на заборе (они не тратятся).
  Прополотая клетка — обычная грядка: сервер учитывает это при посадке, клиент — подменяя символ карты (`withWeeded`).
  Прополка анимирована (`game/effects.ts`): три удара мотыгой, персонаж приседает в такт, из клетки дугой вылетают
  клочки сорняков и комья земли. Анимация — чистые функции от времени (без случайности), запрос к серверу идёт
  параллельно, а грядка меняется ближе к концу анимации.
- **Оживление сада поместья**: поручение Мяты вида REVIVE — пробудить все постройки из списка (три лилии рецептами
  за осколки, колодец за сапфир, фонарь за Солнечную искру). Засохшие клумбы оживают, когда в колодце есть вода:
  у клетки в легенде `revive` (во что превращается и от какой постройки), клиент подменяет символы (`withRevived`).
  Тропа к озеру — дверь с `requiresErrand`: открывается, только когда Мята довольна садом.
- **Секретки**: тайники с `hidden` не мерцают, у каждого своя надпись на кнопке (`action_label`: «Подвести стрелки»,
  «Покачаться», «Постучать»…). В коллекции — счётчик «Секреты: N из M», без подсказок, где искать.
  Пасхалки облика: у Вереска и жителей есть `secrets` («слот:вариант» → разговор) — например, Вереск замечает шляпу колдуна.
  Показываются один раз (помнит браузер), наград за них нет.
- **Цветной свет**: у источника может быть свой цвет — окна и фонари светят тёплым, исполинские лилии
  и цветущая вишня — светло-розовым (в каждом пикселе отсвет берёт цвет самого сильного источника).
- **Для разработки**: `?at=<локация>` в адресе ставит героя у входа в неё (только в dev-сборке, на прогресс не влияет).
- **Состояние построек на экране**: пробуждена/починена, обыскана (инструменты сняты), замок открыт —
  свой кадр атласа `prop_<kind>_<состояние>`, а если такого кадра нет — обычный.

## Жители (мыши)

- Живут в карте локации (`npcs`): имя, спрайт, клетка, описание и разговоры — тот же граф реплик, что у Вереска.
  Сервер проверяет граф при старте. Наград и флагов у них нет, поэтому разговоры с мышами идут только на клиенте:
  первый — знакомство (`talks[0]`), дальше — случайный; кого уже встречали, помнит браузер (localStorage).
- Мыши стоят в своих клетках (через них не пройти) и раз в пару секунд шевелят ушами и хвостом — два кадра атласа.
- Окно разговора общее (`DialogueBox`): Вереску оно сообщает о конце разговора серверу (`MentorDialogue`), мышам — нет.

## Глава 2: туман над озером

Над Туманным озером висит туман (`fog` в `lake.json`). Он начинает редеть, когда выполнено поручение
`after` (Мята: сад поместья ожил), и тает с каждым **днём**, в который игрок отметил хоть одну привычку:
`FogService` считает `count(DISTINCT completed_on)` в `habit_completion` начиная с даты флага
`errand_done:<after>` по часовому поясу игрока. Считаются дни, а не отметки; пропуски ничего не отнимают —
туман никогда не сгущается. Через `days` таких дней он рассеивается, и двери с `requiresFog` (лодка) открываются.

Считает сервер по отметкам, которые сам записал, — подделать с клиента нельзя. Клиент только показывает:
густоту тумана на карте (`drawFog`: дымка над водой и медленные клубы), разговор рассказчика `speaker`
(`talks`: густой → редеет → рассеялся; новость Тишь говорит сразу, как только она появилась),
зарубки на причале (`notches`) и строку в списке заданий.

## Глава 2: городок у мельницы

Когда туман рассеялся, лодка на озере (`requiresFog`) везёт в городок у мельницы (`town.json`):
домик Агаты, мельница, цветочный прилавок, доска объявлений. Там семья Агаты:

- жители-люди задаются **обликом** (`appearance`: слот → вариант, как у героя) и собираются клиентом из тех же
  слоёв атласа, что и герой (`composeCharacter`) — новых спрайтов не нужно; портрет в разговоре — оттуда же;
- поручения: Агата (ромашка → розы), Лиза (сапфир → ирисы), Ника (подсолнух → маргаритки), Тимоша — разговоры;
- новые растения: ирис, роза, маргаритки. Их семена в лавке появляются после поручения Лизы
  (`item_def.unlock_errand`, миграция V12): пока поручение не выполнено, товар скрыт, а сервер отказывает в покупке (409).

## Глава 2: возвращение и субботний хлеб

Жители могут **переезжать**: `leavesAfter` — житель уходит с карты после поручения, `appearsAfter` — появляется
после него (на другой карте — отдельной записью). Так семья Агаты, получив помощь в городке, уплывает домой
и встречается в поместье: Агата и Тимоша на кухне, Лиза у клумб, Ника у дуба.

Агата дома просит разжечь очаг (REVIVE-поручение, рецепт `light_hearth`: два осколка янтаря и Солнечная искра).
Дальше — **субботний хлеб** (`bread` в `kitchen.json`, `BreadService`): раз в неделю, в субботу по часовому поясу
игрока, каравай из `base` + число дней этой недели (с понедельника) с отметками привычек Семян жизни.
Один раз в неделю держит флаг `bread:<год>-W<неделя>`; пропущенная суббота ничего не отнимает.
Это первая награда **за неделю**, а не за день: она поощряет возвращаться, а не идеальную серию.
Для тестирования — кнопка «Сегодня суббота» (флаг `test_bread_day`).

## Глава 3: старая плотина

Из городка вверх по реке — тропа к плотине (`dam.json`), открывается, когда Агата дома (очаг разожжён).
Реку перегородили бобры: их хатку затопило. Канава к саду пересохла (клетки `c` — `revive` в воду, когда
пробуждена `beaver-lodge`).

- Мельник Жернов — за осколок рубина отдаёт шляпу садовника (предмет `gardener_hat`).
- Бобриха Тина — REVIVE-поручение: хатка (рецепт `build_lodge`: два изумруда и сапфир). Хатка построена —
  шлюз открыт, канава наполняется.
- Садовник Ефим — две записи: грустный (`leavesAfter: beaver_lodge`) и оживший (`appearsAfter: beaver_lodge`)
  с поручением вернуть шляпу; после него Ефим появляется дома, у сарая (`gardener-home` в `home.json`).

Кнопка тестирования «Открыть все тропы» выполняет только поручения, которых ждут двери (и сторожа на тропе),
а сюжет главы оставляет игроку.

## Лунная поляна (ночью)

С Восточной тропы — тропка на Лунную поляну (`glade.json`), видна только **ночью**: двери с `requiresNight`
открыты, когда у игрока с 20:00 до 6:00 по его часовому поясу (`NightService`, `night` в `/api/state`).
Днём описание тропки подсказывает прийти вечером. Для тестирования — кнопка «Ночь / день» (флаг `test_night`).

- Клетки `moonflowers` светятся сами (`TILE_LIGHTS`, голубой `MOON_GLOW`); выросшие лунные цветы в саду
  светятся тоже (`GLOWING_PLANTS`).
- Хмур-фонарщик (`appearsAfter: khmur_toll`) — REVIVE: три каменных фонаря, по аметисту (`light_glade_lamp_N`).
- Сова Ухта — SHOW: лунный камень у пруда (находка и артефакт `moonstone`) → семена лунного цветка;
  после этого они продаются в лавке (`unlock_errand: owl_moonstone`).

## Светлолесье (глухая чаща за Лунной поляной)

С Лунной поляны — заросший проход (`requiresNight` и `requiresErrand: khmur_lamps`) в Светлолесье (`dreamwood.json`):
глухую часть чащи, куда никто не заходит, — поэтому всё там светится нетронутым.

- Новые клетки: `dreamgrass` и `stardust` (по ним ходят), `glowshrooms` и `starwater` (светятся сами).
- Существа светятся сами (`CREATURE_GLOW` по виду жителя). Жители могут быть крупнее героя:
  кадр рисуется по центру своей клетки любого размера (большие кошки — 64×56).
- Мурлана, хозяйка чащи — REVIVE: два хрустальных дерева (аметист + сапфир в каждое);
  Тень — ночной кот-страж (разговоры); котёнок Искорка — SHOW: колокольчик в светящемся кусте (артефакт).

## Грибная лощина (за Светлолесьем)

Когда Мурлана получила свои хрустальные деревья (`murlana_trees`), в Светлолесье открывается тропка вглубь (`dream-deep-path`) — в Грибную лощину (`hollow.json`). Там живёт моховой кот Мох, а под землёй спит грибница: семь клеток `mycelium`. Конфиг карты `glow` (`after`, `days`, `speaker`, `talks`): с каждым днём, когда отмечена хотя бы одна привычка после `after`, загорается ещё одна клетка (по порядку чтения строк; клиент подменяет её на `mycelium_lit`, `withGlow`). Пропуски ничего не гасят.

Дни считает сервер: `ReturnDays` — общий подсчёт дней-возвращений для тумана (`FogService`) и грибницы (`GlowService`); `/api/state` отдаёт `glow`. Поручение Мха `mokh_glow` нового вида `GLOW` выполняется, только когда горит вся грибница. Тестовая кнопка «+1 день с привычками» добавляет день и туману, и грибнице.

## Грядки по всему миру и разговоры о привычках

Сажать можно не только дома: на поместье, в городке, у озера, у плотины, на Лунной поляне, в Светлолесье и в восточном лесу есть свои грядки — клетки с `plantable: true` (`bed` — рыхлая земля с травяной кромкой, в Светлолесье и лощине — `moss_bed`; к каждой ведёт тропинка). `POST /api/garden/plantings` принимает `gardenKey` (без него — домашний сад); растение хранится с ключом локации, `/api/state` отдаёт растения всех локаций, клиент рисует на карте только свои (`plantsOn`). Грядки поставлены так, что даже полностью засаженные (растения загораживают клетку) не отрезают ни одного угла карты.

У каждого важного жителя есть разговор `<житель>_habit` — своя мысль о привычках: маленький шаг (Вереск), зёрнышко к зёрнышку (Крупка), вернуться после пропуска (Ветошь), отдых как часть дела (Мята), привязать новое к старому (Шуршик), перемены видны не сразу (Тишь), просить помощи (Ефим), ручей, а не волна (Жернов), свет копится (Мурлана) и другие. Без укоров: пропуск — не провал.

## Контент

Растения и предметы — это данные, а не код. Они описаны в
`backend/src/main/resources/db/migration/R__content.sql`. Это repeatable-миграция:
Flyway перезапускает её при каждом изменении файла, а upsert обновляет существующие строки.
Чтобы добавить растение, достаточно дописать строки в этот файл, Java-код менять не нужно.
