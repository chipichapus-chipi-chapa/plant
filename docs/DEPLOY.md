# Запуск в Telegram

Игра — Telegram Mini App: у бота кнопка «Играть», она открывает сайт с игрой прямо в Telegram.
Ничего не работает с компьютера разработчика:

| Часть | Где живёт | Как обновляется |
|---|---|---|
| Фронтенд (сайт) | GitHub Pages — `https://chipichapus-chipi-chapa.github.io/plant/` (страница установки), игра — в `app/` | `.github/workflows/pages.yml` при пуше в `main` |
| Сервер (Spring Boot) | Render, бесплатный тариф, образ из `backend/Dockerfile` | `render.yaml`, автодеплой при пуше в `main` |
| База (PostgreSQL) | Neon, бесплатный тариф | Flyway накатывает миграции при старте сервера |
| Бот | тот же сервер: `TelegramBot` + webhook `/telegram/webhook` | регистрируется сам при старте |

## Как устроен вход

Telegram передаёт Mini App строку `initData`, подписанную токеном бота. Фронтенд кладёт её
в заголовок `X-Telegram-Init-Data` каждого запроса, сервер проверяет подпись (HMAC-SHA256,
`TelegramInitData`) и находит или создаёт игрока `tg:<id>`. Подделать строку без токена нельзя,
поэтому пароли и сессии не нужны. Токен бота живёт только в переменных окружения Render.

Вне Telegram (приложение на экране телефона или просто браузер) — **вход без регистрации**:
при первом запуске фронтенд вызывает `POST /api/auth/device` и получает случайный ключ устройства
(32 байта), хранит его в `localStorage` и шлёт в заголовке `X-Device-Token`. Сервер хранит только
SHA-256 ключа (таблица `device_token`), игрок называется `dev:<uuid>`. Обе проверки — в `LoginFilter`.

**Привязка к Telegram** (`DeviceAccounts`): в настройках «Привязать Telegram» → сервер выдаёт
одноразовый код (15 минут) → приложение открывает `t.me/<бот>?start=link_<код>` → человек жмёт
«Старт», бот получает `/start link_<код>` вместе с его Telegram id и связывает сад:
если сада в боте ещё не было — сад приложения переименовывается в `tg:<id>` и становится общим;
если был — ключи устройства переключаются на сад из бота, а анонимный сад удаляется.
Приложение тем временем опрашивает `GET /api/auth/telegram-link/<код>` и, дождавшись, перезагружается.

Режим включается переменной `TELEGRAM_BOT_TOKEN`. Без неё сервер работает по-старому —
один локальный игрок — и отказывается стартовать, если его пытаются открыть в сеть.

## Первая настройка (один раз)

1. **База — Neon.** Войдите на neon.tech через GitHub → New project (регион Frankfurt) →
   Connection string, вариант без `-pooler`. Из `postgresql://USER:PASSWORD@HOST/DB?sslmode=require`
   понадобятся три значения:
   - `SPRING_DATASOURCE_URL` = `jdbc:postgresql://HOST/DB?sslmode=require`
   - `SPRING_DATASOURCE_USERNAME` = `USER`
   - `SPRING_DATASOURCE_PASSWORD` = `PASSWORD`
2. **Сервер — Render.** Войдите на render.com через GitHub → New → Blueprint → репозиторий `plant`.
   Render прочитает `render.yaml` и попросит секреты: три значения из Neon и `TELEGRAM_BOT_TOKEN`
   (выдал @BotFather). Первая сборка идёт ~5 минут. Адрес сервера будет вида
   `https://where-it-grows.onrender.com`; проверка — `/actuator/health` отвечает `UP`.
3. **Сайт — GitHub Pages.** В репозитории Settings → Pages → Source: **GitHub Actions**.
   Settings → Secrets and variables → Actions → Variables → New variable:
   `API_URL` = адрес сервера из шага 2 (без `/` в конце). Затем Actions → Pages → Run workflow.
4. **Бот** настраивается сам. При старте сервер берёт свой внешний адрес (`RENDER_EXTERNAL_URL`,
   его задаёт Render) и адрес игры (`TELEGRAM_WEB_APP_URL` из `render.yaml`) и вызывает Bot API:
   `setWebhook` — Telegram присылает сообщения боту на `/telegram/webhook` с секретом в заголовке
   (секрет выводится из токена, чужие запросы получают 403); `setChatMenuButton` — кнопка «Играть».
   На `/start` и любое сообщение бот отвечает приветствием с кнопкой входа в сад.
   По желанию в @BotFather `/newapp` даст ещё и прямую ссылку вида `t.me/<бот>/<имя>`.

Дальше всё обновляется само: пуш в `main` пересобирает и сайт, и сервер.

## Тестирование

В настройках игры есть раздел «Тестирование»: выдать ресурсы, открыть все тропы до озера, «Туман +1 день»,
«Рассеять туман», «Сбросить прогресс» (имя и облик остаются). Кнопки меняют только свой сад.

- Локально (без `TELEGRAM_BOT_TOKEN`) они видны всегда.
- На сервере — только тем, чей Telegram id перечислен в `GAME_TESTERS` (Render → Environment, через запятую).
  Свой id подскажет бот: напишите ему `/id`. Остальным игрокам кнопки не видны, сервер отвечает им 403.
- Туман ускоряется флагами `test_fog_day:N`, а не поддельными отметками привычек — трекер остаётся честным.

## Что нужно знать

- Бесплатный сервер Render засыпает после 15 минут без запросов. Первый вход после паузы
  (и первый ответ бота) ждёт около минуты — игра покажет «Сервер сада не отвечает», кнопка «Попробовать ещё раз» поможет.
- Если токен бота попал куда не следует — `/revoke` в @BotFather и новый токен в Render
  (Environment → `TELEGRAM_BOT_TOKEN`). Прогресс игроков не пострадает: он привязан к их Telegram id.
- Открыть сайт в обычном браузере можно, но сервер ответит «Нужен вход через Telegram».
  Для разработки по-прежнему: локальный backend без токена и `npm run dev`.
